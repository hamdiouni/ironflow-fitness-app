# Audit Track I — Release Engineering, Flavors, Consent, and Observability

| ID | Severity | Finding | Measured Evidence | Prescribed Fix | Effort | Wave |
| :--- | :---: | :--- | :--- | :--- | :---: | :---: |
| **OPS-01** | **P0 HIGH** | Telemetry (Analytics & Crashlytics) defaults to opt-out (`true`) instead of opt-in (`false`) | `lib/core/services/telemetry_preferences.dart:29,36` and `lib/features/settings/presentation/screens/privacy_settings_screen.dart:60-61` use `prefs.getBool('analytics_enabled') ?? true` and `prefs.getBool('crash_reporting_enabled') ?? true`. This contradicts the Privacy-First rule ("analytics and crash reports only with consent"). | Change default in `TelemetryPreferences` and `PrivacySettingsScreen` to `false` (opt-in only), disable auto-collection in `AndroidManifest.xml` / `Info.plist` until consent is granted, and add a clear opt-in toggle during onboarding/settings. | 3h | W1.8 |
| **OPS-02** | **P1 HIGH** | No `dev` / `staging` / `production` build flavors | `android/app/build.gradle.kts` has a single applicationId (`com.progressiontracker.progression_tracker`) and single `google-services.json`. Developers cannot install `dev` and `prod` side by side or isolate staging Firebase data from production. | Configure `dev`, `staging`, and `prod` flavors on Android, iOS, and Web using `--dart-define-from-file=config/<flavor>.json` with separate app IDs, names, and Firebase targets. | 6h | W2.5 |
| **OPS-03** | **P1 MEDIUM** | Missing Crashlytics Gradle plugin & feature flag / kill-switch infrastructure | `firebase_crashlytics` is in `pubspec.yaml`, but `com.google.firebase.crashlytics` is not applied in `android/settings.gradle.kts` or `android/app/build.gradle.kts`. No remote feature flag / kill-switch service exists to disable cloud sync or AI proxy remotely during an incident. | Apply Crashlytics Gradle plugin and add a lightweight Remote Config / feature-flag abstraction (`FeatureFlagsService` with safe local defaults + remote override; see ADR-005). | 4h | W2.7 |
| **OPS-04** | **P2 LOW** | Build stamp in Settings > About | `pubspec.yaml` version is `1.1.0+2`. Need to ensure `GIT_COMMIT` and `BUILD_DATE` passed via `--dart-define` are consistently displayed in Settings > About and diagnostic reports. | Standardize build-stamp defines in `scripts/run_web.ps1` and CI builds. | 2h | W2.6 |
