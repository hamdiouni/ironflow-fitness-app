# Audit Track B — Backend, Firestore Rules, Storage Rules, and Sync

| ID | Severity | Finding | Measured Evidence | Prescribed Fix | Effort | Wave |
| :--- | :---: | :--- | :--- | :--- | :---: | :---: |
| **BKD-01** | **P0 CRITICAL** | Cross-user document hijack vulnerability in `firestore.rules` | `firestore.rules:34-37, 65-83`: On `/workouts/{workoutId}`, `/programs/{programId}`, `/nutrition/{logId}`, and `/body_progress/{progressId}`, `allow create, update: if writesOwnDoc();` checks ONLY `request.resource.data.userId == request.auth.uid` and does **not** check `resource.data.userId == request.auth.uid` on `update`. Any authenticated user who knows or guesses a document ID can overwrite and claim another user's record. | Separate `allow create: if writesOwnDoc() && isValidPayload();` from `allow update: if readsOwnDoc() && writesOwnDoc() && isValidPayload();`. Add emulator unit tests proving cross-user `update` is denied. | 4h | W1.3 |
| **BKD-02** | **P0 CRITICAL** | Broken file deletion in `storage.rules` | `storage.rules:16-38`: `allow write: if isOwner(userId) && request.resource.size < ... && request.resource.contentType.matches(...);`. In Firebase Storage, `delete` is evaluated under `write` with `request.resource == null`, causing `request.resource.size` to fail and **denying every file deletion** (including account deletion purge!). | Split `allow write` into `allow create, update: if isOwner(userId) && request.resource != null && ...;` and `allow delete: if isOwner(userId);`. Add Storage emulator rules tests. | 2h | W1.3 |
| **BKD-03** | **P0 CRITICAL** | `RemoteDataPurgerImpl` silently swallows errors and skips Storage subfolders | `lib/features/settings/data/repositories/remote_data_purger_impl.dart:54,72,80,97,108,121`: Every Firestore/Storage delete block catches `e` and logs a debug note without rethrowing, so `DeleteAccountUseCase` proceeds to delete the Firebase Auth account even when cloud data deletion failed. Additionally, lines `116-120` only iterate `userStorageRef.listAll().items` and ignore `listResult.prefixes` (`profile/`, `workouts/`, `progress/`), leaving 100% of user photos/videos orphaned in Storage. | Recurse into `listResult.prefixes` (`profile`, `workouts`, `progress`), aggregate failures, and throw a typed `RemotePurgeException` if any collection or storage prefix fails to purge. | 4h | W1.5 |
| **BKD-04** | **P0 HIGH** | Missing field & size validation in `firestore.rules` | `firestore.rules:47-88`: Neither `/users/{userId}/**` nor the flat sync collections validate field types, string lengths, or document sizes (`request.resource.data.keys().size()`), allowing a malicious client to store megabyte blobs in Firestore documents. | Add schema/size guard helpers in `firestore.rules` (e.g. `userId is string`, `updatedAt is string || updatedAt is timestamp`, max keys count, max string lengths) and verify with Firebase Rules Emulator tests. | 4h | W1.3 |
| **BKD-05** | **P1 HIGH** | Sync conflict resolution, ordering, and partial failures | `lib/features/sync/` (31.5% line coverage in `lcov.info`): Uses a local `hive_sync_queue_datasource.dart` and `firestore_sync_datasource.dart`. Needs explicit, documented conflict resolution rules (Last-Write-Wins via monotonic `updatedAt` + tie-breaker, tombstone `deletedAt` precedence over stale updates), idempotent batch commits, and multi-device conflict tests. | Document conflict specification in `docs/architecture/SYNC_SPEC.md`, add characterization + two-device conflict tests, and gate cloud sync behind a remote/feature flag until all tests pass. | 8h | W1.6 |
